# Hackathon: your steps

**Google Search AI plans. Qoder implements. You check and submit.**

## Before starting

- Open the permitted Google Search AI interface and Qoder. Check your credit
  balance. Start with Efficient if it still shows 0.0x; use Auto when it struggles.
  Fast replaces the old Performance tier if you need faster turnaround.
- Keep the [playbook](HACKATHON-PLAYBOOK.md) open for copy-ready prompts. Give
  both tools the original brief and rubric PDF. Give Qoder the short rules and
  agreed plan as well; it does not need this whole playbook.

## On the day

1. **Read the brief and rubric yourself.** Note the deadline, required stack,
   marks and submission rules. Save the original files. Make sure both tools can
   read every rubric page, including tables and full-mark descriptors.
2. **Plan in Google.** Use playbook prompt A with the complete brief/rubric and
   actual starter facts: file tree, dependency manifest, run scripts and relevant
   code. If there is no starter, say so. Answer essential questions, then use B.
3. **Check and save the plan.** Confirm every full-mark rubric item is covered,
   with its page reference and a way to verify it. Save the
   complete execution plan as `EXECUTION-PLAN.md` and the checklist/decisions as
   `HACKATHON-STATUS.md` in the assessment project.
4. **Start Qoder.** Attach/reference the original rubric PDF, brief, short rules
   and execution plan; send
   prompt C. Let it work through related steps continuously. You do not need to
   send a new prompt after every task.
5. **Check progress.** At useful milestones, inspect changes, try the app and run
   routine checks yourself. Record real results in the checklist, check credits
   and save working Git milestones. Keep **600 credits for late blockers**.
6. **Handle blockers.** Let Qoder fix straightforward local errors. If it stops
   after repeated failures or needs a design change, give Google prompt D with
   the exact error, current relevant code and attempted fixes. Send the resulting
   narrow fix to Qoder; verify the result.
7. **Review and submit.** From about hour 6, use Qoder prompt E for a final check
   against the original PDF, then Google prompt F with that evidence to find gaps.
   Resolve missing, partial and unverified items. Reserve the last 45 minutes.
   Run required checks, follow your app's run instructions in a fresh copy, then
   complete and verify the submission. If Git delivery is required, verify the push.

Google cannot see your files unless you supply them. Qoder saying "done" is not
proof: check the required behavior yourself.

`this_is_a_test.md` is an older practice guide. Use the new brief's timing and
submission rules for this nine-hour event.
